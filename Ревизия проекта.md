Прошёлся по всем 12 файлам. Собираю итоговый отчёт — по важности находок, от критичных к косметическим.

### 1. Полностью мёртвый файл — `scripts/generateBootstrapImports.mjs`

Экспортирует `buildBootstrapImports()`, но эта функция **не импортируется никем**: ни в `build.mjs`, ни в `styles.mjs`, ни в `package.json` scripts. Дополнительные признаки, что это заброшенный эксперимент, а не "скрытая" часть пайплайна:

- Использует устаревший Sass-синтаксис `@import` — а весь остальной проект (README, `generateStyle.mjs`) построен вокруг современного `@use`.
- Логирует через голый `console.log/warn/error`, а не через общий `logger.mjs`, как вообще все остальные файлы проекта.
- Тег `[generateBootstrapImports]` даже не зарегистрирован в палитре цветов `logger.mjs`.

Похоже на раннюю попытку автоматически генерировать порядок `@import` для Bootstrap, от которой отказались в пользу текущего подхода (`addCssBefore` в `projectConfig.json` + `@use`). Стоит либо удалить файл, либо, если идея ещё актуальна, — подключить к пайплайну и переписать под `@use`/общий логгер.

### 2. README вводит в заблуждение про `npm run create-block`

Документация утверждает:

```
npm run create-block
# Введите имя блока: my-block
```

— то есть описывает интерактивный ввод. Но реальный `createBlock.mjs` читает имя блока из `process.argv[2]` — это обычный CLI-аргумент, никакого `readline`/интерактивного промпта в коде нет. Реальный вызов должен выглядеть так:

```
npm run create-block -- my-block
```

(с `--`, чтобы npm передал аргумент дальше). Без `--` имя блока не долетит, и скрипт завершится с `[createBlock] Отмена операции: не указано имя блока`. Стоит поправить пример в README, чтобы не путать себя же через пару месяцев паузы.

### 3. Ещё один файл на `var` без обёртки `isMainModule` — `scripts/img-opt.mjs`

Как и `deploy.mjs`/`assets.mjs` раньше — весь файл на `var` вместо `const`/`let`. Дополнительно, в отличие от всех остальных скриптов (`build.mjs`, `clean.mjs`, `styles.mjs` и т.д.), здесь нет паттерна `export async function ...`  + проверка `isMainModule` — код выполняется сразу на верхнем уровне модуля при импорте. Раз это чисто CLI-утилита (`npm run img:opt -- ...`), это не баг, но нарушает единообразие остальных файлов. Если хотите — могу как и раньше просто заменить `var`→`const`/`let`, дословно, без изменения логики.

### 4. Комментарий-план в `build.mjs` не совпадает с реальным порядком вызовов

JSDoc гласит:

```
* Последовательность:
* 1) clean 2) generateStyle 3) sprite-svg 4) styles 5) scripts 6) assets 7) html
```

А по факту код вызывает:

javascript

```javascript
await cleanBuild();
await generateStyleEntry();
await buildStyles({ mode });
await buildScripts({ mode });
await copyAssets();
await buildSvgSprite(); // после copyAssets, чтобы не перезаписать свежий спрайт
await buildHtml({ mode });
```

То есть спрайт реально собирается **после** ассетов, а не третьим шагом, как написано в комментарии — сам код при этом корректен и даже объясняет почему (инлайн-комментарий про перезапись), просто JSDoc устарел и не обновлялся при этом решении. Косметика, но вводит в заблуждение при беглом чтении.

### 5. Неиспользуемые зависимости в `package.json`

`styles.mjs` подключает только `autoprefixer`, `postcss-sort-media-queries`, `postcss-inline-svg`. А в `devDependencies` ещё числятся `postcss-calc`, `postcss-pxtorem`, `postcss-extract-media-query` — и `customPostcss.js` (единственное место, куда пользователь мог бы их добавить) сейчас содержит `export default [];` — то есть они нигде фактически не используются. Либо это заготовки на будущее ("могут понадобиться"), либо стоит убрать из `package.json`, чтобы не тащить лишний вес в `node_modules` и не путать при следующем ревью зависимостей.

### 6. Мелкие косметические штрихи (не критично)

- `logger.mjs`: ~47 из 88 строк — закомментированная шпаргалка по API `chalk`. Работе не мешает, но раздувает файл более чем вдвое.
- `config.mjs`: комментарий упоминает "аналогично функции getFilesList из gulpfile.js проекта ugspot" — историческая справка про давно неактуальный источник вдохновения, можно убрать или оставить как есть, на ваш вкус.
- `scripts.mjs`: нумерация шагов в комментариях начинается с "2." (нет явного "1." перед фильтрацией блоковых JS-файлов) — не ошибка, просто не хватает одной строки для полноты.
